## d) TOTALLY FUCKED UP

### 1. Tag Pushed BEFORE Secret Configured — Wrong Order of Operations

**What happened:** I pushed the v0.1.1 tag at `17:08:20Z`. The `publish.yml`
workflow triggered immediately and failed because `CARGO_REGISTRY_TOKEN`
didn't exist yet. I then manually published via `cargo publish` at `17:08:42Z`
and set the secret at `17:09:51Z` — about 90 seconds after the tag push.

**Root cause:** I treated the secret configuration as step 11 (after publish)
instead of step 0 (before tagging). The correct sequence is:

1. Set the secret
2. Bump version + CHANGELOG
3. Commit
4. Tag
5. Push tag → workflow publishes automatically

**The fix is permanent:** The secret now exists. Future releases will
publish automatically. But the v0.1.1 Actions tab permanently shows a failure.

**Severity:** Low-moderate (process mistake, not a code defect. The crate is
correctly published. But it looks unprofessional in the Actions history.)

### 2. No Process for Verifying docs.rs Before Declaring Done

I declared the release done without verifying docs.rs built v0.1.1. This is the
same "verify before claiming done" pattern from the prior session. docs.rs is
the primary documentation surface for Rust crates — it should be verified.

**Severity:** Low (almost certainly fine, but unverified)
