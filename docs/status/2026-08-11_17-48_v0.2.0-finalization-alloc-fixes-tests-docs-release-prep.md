## b) PARTIALLY DONE

### 1. `Arc<Vec<...>>` for span field extensions — DEFERRED

I attempted to change `CapturedSpanFields` from `Vec<(String, String)>` to
`Arc<Vec<(String, String)>>` and `SpanContext.fields` to `Arc<Vec<...>>` for
O(1) per-event clones. This hit two blockers:

1. **serde**: `Arc<Vec<...>>` doesn't implement `Serialize`/`Deserialize`
   without the `rc` feature on serde. Adding `features = ["rc"]` to the serde
   dependency would work for serialization but changes the deserialization
   semantics.
2. **utoipa**: `ToSchema` derive panics on `Arc<Vec<...>>` fields — there's no
   built-in schema mapping for `Arc`.

I tried it, confirmed it doesn't compile under `--all-features`, and reverted.
Documented as a TODO with the specific blockers. This was the right call — the
optimization isn't worth adding serde `rc` + a utoipa workaround for a 0.2.0
release.

1. `is_sensitive_field` zero-allocation matching — **DONE** (prior session)

## e) WHAT WE SHOULD IMPROVE

### Process

1. **Compound todos are still tempting.** The prior session's failure was
   putting 3 sub-tasks in one todo. This session I split them correctly and
   each was trivial. Lesson reinforced: one todo = one change.

2. **Test target alignment.** When writing a test with `EnvFilter`, the filter
   target must match the event/span `target:` attribute. I burned a round-trip
   on this. Next time, copy the exact target from the filter into the macro
   calls from the start.

3. **`Arc` + serde + utoipa is a known pain point.** Before attempting to
   `Arc`-wrap any type that derives `Serialize`/`Deserialize`/`ToSchema`, check
   whether serde `rc` feature is enabled and whether utoipa supports it. This
   combination is a recurring trap in the Rust ecosystem.

### Technical

4. **`SpanContext.fields` should eventually be `Cow` or `Arc`.** The per-event
   clone of span fields is O(n fields). For a span with 10 fields and 1000
   events inside it, that's 10,000 string clones. The `Arc` approach is blocked
   by serde/utoipa, but a `Cow<'static, ...>` or a custom `Deserialize` impl
   could work around it.

5. **The proptest had latent index-out-of-bounds bugs.** Extending the range
   to `0` exposed two assertions that assumed `snap` was non-empty. This means
   the proptest was never truly testing the edge — it was always implicitly
   guarded by `capacity >= 1`. Lesson: property tests should explicitly cover
   boundary values, not just "small" values.

6. **The memory footprint test gives a false sense of precision.** "~237 KB"
   has three significant figures but is off by 30-50%. A precise wrong number
   is worse than an imprecise honest one.
